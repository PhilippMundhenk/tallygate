Grant requests

The agent asks for a predefined bundle of access. The reason is written by the agent – treat it as a claim, not a fact.

Pending connection requests

Connections are held until you decide or the timeout passes (then denied). Hard-denied targets (LAN etc.) never appear here.

Which button should I use?
  • Allow 2 min: one operation (an install, a clone). Follow-up connections in that time are covered.
  • Allow 1 h: a working session with this host.
  • Always (host): a permanent rule for exactly this host and port.
  • Always (*.domain): the domain and every subdomain, e.g. all of *.githubusercontent.com. Check the domain line first: github.com.evil.example belongs to evil.example.
  • Deny: refuse now; the agent may ask again later. Block forever: a permanent deny rule, no more prompts.

Every decision becomes a normal rule you can review or delete under Rules. More

Emergency stop revokes all active grants, denies everything still waiting for approval, undoes the internet shortcuts above, blocks everything unknown and suspends automatic grant approval until you change the mode again. Claude itself stays reachable through your allow rules.

Local network

The local network, the Docker host and cloud metadata addresses are always blocked (hard deny): no rule can open them. To let the agent reach one device, define a grant: exact host and port, a time limit, and your approval each time it is used.

Action
allow lets it through, deny refuses without asking, ask holds it and asks you.

        
Host
An exact name (pypi.org), a domain with all subdomains (*.github.com, also matches github.com), or * for every host.

        
CIDR
An IP range such as 203.0.113.0/24. allow/ask cover connections to IPs only, never names that resolve into the range; deny covers both.

        
Ports
443, 80,443, a range 8000-8100, or * / empty for all ports.

        
TTL
Seconds until the rule expires, e.g. 3600; empty = permanent.

      

      
How are rules applied?
        
The first matching rule from the top decides; new rules are added at the top. Before any rule, the
          hard deny refuses the local network, the Docker host and cloud metadata, and no rule can change that.
          Names are decided before they are resolved, so a denied name never reaches DNS. When no rule matches, the
          mode decides (ask, deny or allow). Use Test a destination to see what a rule does.

        
Examples: allow *.npmjs.org 443 · deny telemetry.example.org * ·
          ask *.pastebin.com * · allow 203.0.113.10/32 22.

Defined grants

    
A grant bundles targets (host:port, optionally HTTP paths), access levels (read = GET/HEAD/OPTIONS
      only, write = everything), LAN access, credential injection and how each level is approved. The agent can
      request them with tallygate request <name>; grants from the config file are read-only here.

    

    

    

      
New grant

      

        
        
      

      

        
        
        
        
        
        
      

      
read allows only GET, HEAD and OPTIONS (no uploads, no WebSockets); write allows
        everything. ask means you approve each request; auto grants it without asking (sensible for read
        on harmless APIs). Durations: 30m, 2h, 1d; the agent may ask for less, never more than the maximum.

      
Targets

      
https/http targets are inspected per request (method, path, Host). tcp passes raw traffic (write level only).
        LAN exempts exactly this target from the hard deny (UI grants only within –).
        Self-signed certificate? Pin its SHA-256 fingerprint instead of disabling verification.

      
Target examples
        
    
          
  • Home Assistant API, read-only: http · ha.lan · 8123 · paths /api/* · LAN
    • 
          
  • Proxmox with a self-signed cert: https · pve.lan · 8006 · paths /api2/json/* · LAN · fingerprint from
            openssl s_client -connect pve.lan:8006 </dev/null | openssl x509 -noout -fingerprint -sha256
    • 
          
  • SSH to one machine: tcp · nas.lan · 22 · LAN (tcp needs the write level)
    • 
          
  • A public API, only some paths: https · api.example.com · 443 · paths /v1/items/*, /v1/search
    • 
        

        
Paths are globs: * matches any characters including /, so /api/* covers
          /api/states and /api/states/light.kitchen; the query string is not part of the path. Several patterns are comma-separated.
          fixed IP pins the address instead of resolving the name.

Secrets for credential injection
      
Write-only: values are stored in the gateway and can never be read back. Reference them in a
        header template as ${name}, e.g. Bearer ${ha_token}.
